# Changelog

All notable changes to this profile repository are documented here.

## [Unreleased]

- **Changelog tab, finer kinds:** the entries of the changelogs are placed with two new kinds (versions / maintenance, and build / CI / tooling), a new `patterns` rule in `changelog.kinds` for the way an entry begins (tried only when no word matched, so a beginning never beats a word), and the order docs before tests; the entries that no rule recognises fall from about 24 % to about 8 %, with a hand-checked precision of about 93 % on a random sample, and the tests keep real wordings of every kind, the ambiguous ones included. The texts of the two new kinds are in the eight languages.
- **Scripts tab:** a tab with the GitHub workflows of every repository (triggers, jobs, runners, the actions they use and whether their version is pinned to a commit, a version tag or a branch) and the scripts of `tools/` and `scripts/` by language, read once a day by `scripts/scripts_stats.py` on the same clones as the code counter and kept in `data/scripts-stats.json`: seven figures, stacked bars by trigger, by pin and by language for the whole, each ecosystem and each type, the most used actions, the repositories with most workflows, the list of actions not pinned to a commit, and a sortable, filterable and groupable table, with the relief and the tooltips of the other tabs and the texts in the eight languages. See `docs/SCRIPTS_STATS.md`.
- **Relief of the charts in the Code, Changelog and Builds tabs:** the stacked bars get the shadow under the track, the dark lower half and the light edge of the other tabs, the donut and the ring a soft shadow and a light arc, the daily columns of the Builds tab the light top face and the dark side face, and its bars the same gradient and inset track; the same entrance animation and theme handling as the rest of the dashboard.
- **Changelog tab:** the statistics of the changelogs are a tab of their own, next to the Code tab, instead of a button inside it; the charts of both tabs use the numeric and axis fonts, the chart width and the label weight of the other tabs, and the key figures keep to one line.
- **Code tab, Changes view (now the Changelog tab):** statistics of the CHANGELOG of every repository, read in the same daily run: published versions and entries, entries waiting under [Unreleased], entries per version, the kind of each entry (bug fix, added, security, documentation, tests, performance, refactor, changed) decided by editable words in `code-stats-config.json`, with the entries that match no rule counted and shown as unclassified, and the pace of publishing from the tags of GitHub. It has a donut and stacked bars of the kinds, lines over time from the daily history, a ranking by volume and by share of fixes, the detail of each repository (its versions and, for the newest ones, the entries, searchable and filterable by kind), a sortable and filterable table and an export of it as CSV or JSON, in the eight languages. See `docs/CODE_STATS.md`.
- **Code tab:** the dashboard has a tab with the lines of code, comments, blank lines, tests and documentation of every repository of the four ecosystems, counted once a day on shallow clones by `scripts/code_stats.py` (standard library only) with the rules, ecosystems and types in `code-stats-config.json`. It shows ten figures, stacked bars of code, tests and documentation (whole, by ecosystem, by type), the mix of programming languages, lines over time from a daily history that is thinned out as it ages, the largest repositories, and a table that can be sorted, filtered and grouped, in the eight languages, with a table and a tooltip for every chart. A new workflow, `code-stats.yml`, runs it daily and on demand with a read-only counting job and a separate publishing job. See `docs/CODE_STATS.md`.
- **Shared contract pins:** the Sentinel tab has a card that lists, per ecosystem, the version of the shared contracts each repository was last checked against (A.R.M.O.R. from the contract pins of its common repository, URTC from the lock file of each repository) next to the current version, as current, behind, ahead or unknown, in the eight languages. HYDRA-UMC publishes no machine readable pins and is shown as such; what cannot be read is never shown as current. See `docs/DEPENDENCY_PINS.md`.
- **Signature and attestation of the latest release:** the Sentinel tab has a card, by ecosystem and by repository, and the panel of each repository two fields, that show whether the release files carry a signature file and a GitHub build attestation (present, partial, absent, not applicable or unknown), in the eight languages. Presence only; the attestation is read for a few files per release, inside the `presence` budget of requests and cache of `dashboard-config.json`, and what could not be read stays unknown. See `docs/SIGNATURE_PRESENCE.md`.
- **Sentinel tab, by ecosystem:** a table with the repositories, the red workflows, the releases ready and the unpublished versions of each ecosystem.
- **Sentinel tab, version raised but not published:** repositories whose manifest declares a version newer than their latest release are listed and appear in the short report.
- **Sentinel tab, recent changes:** a short feed (`sentinel.events_max`) of workflows that turned red or green again and of releases that appeared, kept in `data/sentinel.json`; see `docs/SENTINEL.md`.
- **One criterion for a red build:** the Sentinel tab, the Builds tab and the CI watch issue now share a single definition (`scripts/ci_rules.py`): `failure`, `timed_out`, `startup_failure` and `action_required` on the last finished run of a workflow on the default branch are red; cancelled, skipped, neutral and stale runs are passed over; runs generated for dependency updates never count.
- **The profile has a changelog:** the changes of the profile, the generated README and the status dashboard are listed here from now on.
