# Dashboard UI tests

Browser tests of the ecosystem status dashboard (`docs/index.html`, generated by `scripts/generate_dashboard.py`).

The whole battery runs with `prefers-reduced-motion: reduce` (see `playwright.config.ts`) so that no screenshot or contrast check catches a chart half drawn; the motion tests ask for the animation explicitly.

The tests never read the live page and never call GitHub. The dates of the fixtures are in 2001: tests that depend on the age of a date fix "today" with `page.clock.setFixedTime`. They run against pages generated from deterministic fixture data
(`fixture/build_fixture.py`), in seven variants: `full` (40 projects, four ecosystems, 44 daily snapshots of history with two days missing, with dependencies, weekly activity, milestones and creation dates), `stale` (the full page when GitHub could not be read in the last generation: the CI, release and commit data are the last known version, marked with their date), `single` (the same without earlier history), `healthy` (the same size with nothing wrong, the only one that may say `no alerts`), `minimal` (one project, no activity),
`partial` (every lookup failed) and `empty` (nothing at all). The last two prove the page says "no data" or "not verified" and
never shows a healthy state it does not have.

| `tests/language-theme.spec.ts` | the 8 languages (no visible key, `undefined` or placeholder in any tab), browser language, light/dark theme |
| `tests/filters.spec.ts` | search by name, description, stack and target; each filter alone and combined; the N of M counter; reset; no matches |
| `tests/scope-pager.spec.ts` | the scope bar of the projects tab (All, the four ecosystems, cross-cutting), the families under it, the pager (only one page is painted), the counter N of M with scope plus filters, the scope in the `#hash` and remembered in `localStorage` (with and without storage) |
| `tests/charts.spec.ts` | names of the meters, rings, bars and columns in the 8 languages, tooltips with the mouse and with the keyboard (Escape dismisses), `prefers-reduced-motion` (no animation, same data) and the entrance with motion allowed |
| `tests/health-panel.spec.ts` | the health alerts (red CI, manifest, version, days without activity; `no alerts` only when the data are complete, `incomplete data` otherwise), the stamp of the last published build, the activity badges of the project table at fixed dates (colour, glyph and words), the list of repositories behind every bar, ring and area (mouse, keyboard, languages) and the side panel of a repository (fields, CI, commits or the note that there are none, links, Escape, focus, sizes) |
| `tests/evidence-history-modes.spec.ts` | the evidence checklist (states in glyph and text, filters by ecosystem and by what is missing, counters, side panel, keyboard, no data), the history chart (lines broken at the days without a snapshot, 30 and 90 days, a single snapshot, no history, motion only when allowed), `since your last visit` (changes, none, first visit, blocked or damaged storage), compact and presentation modes (buttons, shortcuts, address, storage), the print report (`emulateMedia` print), icon and share-card metadata, axe in both themes, 1920x1080, 1366x768 and mobile, the 8 languages |
| `tests/insight.spec.ts` | the analysis tab: its six views (buttons and keyboard), the maturity funnel (counts that add up, a funnel that never widens, moves since a month ago, no earlier snapshot), the four radars with their table and without colour alone, the weekly heat map (the number in every cell, releases by date, not verified when unread), dependencies (who uses whom, cycle, missing repository, other ecosystem, search, diagram, node to panel, keyboard), next milestones (source, glyph and word per status, not verified), comparing two dates (only existing snapshots, same date, a snapshot without repositories, fewer than two), technical debt (three rules, not verified), the 8 languages, axe in both themes and on poor data, 1920x1080, 1366x768 and mobile, motion on and off, print, and no request of its own |
| `tests/ci-evidence.spec.ts` | the view "declared against verified" of the evidence tab: a row per repository, the seven states (verified, declares more than it proves, failing, expired, not verified, invalid records, could not be read) in glyph and text with their counters and filters, the repositories that need attention first, nothing published or unreadable never shown as verified, links only to runs inside the repository, the page built without any evidence read, the 8 languages, axe in both themes, 1920x1080, 1366x768 and mobile, and no request of its own |
| `tests/robust-nav.spec.ts` | the keyboard shortcuts and their help (`?`, `/`, `0` to `4`, the old `C` and `P`, off while typing, with a modifier or with the switch, remembered with and without storage, the 8 languages, axe in both themes), the breadcrumb (tab, scope and repository, links, the address in both directions, the 8 languages), the manifest health card (valid manifests over repositories, how it is calculated, not verified without data, untouched by the filters), the figures of the generation and the reason of every unreadable manifest, the last known data (dated notice, never `no alerts`, the 8 languages, the network down, axe), the URTC rack page (alarm, quiet, no data and unusable snapshots, escaped values, translated alarms and verdicts, axe, 1920x1080 and mobile) and the sizes of the new parts |
| `tests/details-links.spec.ts` | disclosures (project notes, errors/unknown), architecture and compatibility switchers, every link is `https` to `github.com/JuanenRac/...`, rows = KPI |
| `tests/data-states.spec.ts` | partial, minimal and empty data; build freshness unknown vs known |
| `tests/responsive.spec.ts` | 1920x1080 (no page scroll), 1366x768, 768x1024 and 390x844 (no horizontal scroll, scrolling tab bar, collapsible filters) |
| `tests/accessibility.spec.ts` | axe-core on every tab, light and dark, English and Japanese (no serious or critical violation); heading order, tab/panel relations, chart alternatives; full keyboard walk with visible focus |
| `../tests/test_dashboard_snapshot.py` | not a browser test: the counts per ecosystem and the indicators of the page built from the fixture are compared with `tests/snapshots/dashboard_fixture.json`, so an accidental change of a figure fails (regenerate it with `UPDATE_SNAPSHOT=1` when the change is intended) |
| `check_html.py` | structure of the generated page: balanced tags, duplicate ids, dangling references, names of controls, required attributes, translation keys in the 8 languages, `data-*` coherence |

axe-core finds only part of the accessibility problems; the keyboard walk and the structure checks cover some of the rest, but a
manual review with a screen reader is still needed.

## Run it locally

Requirements: Python 3.11+, Node.js LTS, and the three updater packages importable by Python (installed with `pip`, or checked out next
to this repository as `HYDRA-UMC-UPDATER`, `URTC-UPDATER` and `ARMOR-UPDATER`).

```bash
cd e2e
npm ci                              # pinned in package-lock.json
npx playwright install chromium    # once; skip it if a matching Chromium is already installed
python fixture/build_fixture.py    # writes fixture/out/{full,minimal,partial,empty}/index.html
python check_html.py fixture/out/full/index.html fixture/out/partial/index.html
python check_html.py ../docs/index.html          # the published page
npx playwright test                # the whole battery
npx playwright test filters        # one file
```

Useful options:

* `FIXTURE_DIR=/path` uses pages generated somewhere else.
* `SHOTS=/path npx playwright test responsive` keeps a screenshot of every tab at every screen size for a visual review.
* The screenshots of failed tests are in `test-results/`.

`node_modules/`, `test-results/` and `fixture/out/` are not committed. The workflow `.github/workflows/dashboard-ui-tests.yml`
runs the same steps on every pull request and push that touches the dashboard.
